# 节点3最低诊断条件结构化规则

## 1. 文档目的

本文用于向 AI 明确说明“节点3：病类判断与诊断条件校验”的设计思想。

节点3不负责诊断具体疾病，也不应依靠模型的主观感觉判断“信息是否足够”。节点3的核心职责是：读取节点2输出的结构化病例信息，按照预先配置的确定性规则，判断疾病方向、检查最低诊断条件，并将流程路由至节点4或节点5。

这里的“满足最低诊断条件”仅表示现有信息足以进入节点5开展知识库检索和辅助诊断，不代表已经能够确诊。

## 2. 节点职责边界

节点3负责：

1. 根据明确症状判断疾病方向；
2. 校验通用必填字段；
3. 校验对应疾病方向的最低字段要求；
4. 输出缺失字段和优先追问字段；
5. 决定进入节点4还是节点5。

节点3不负责：

1. 输出具体疾病诊断；
2. 比较多个候选疾病；
3. 提供治疗、用药或产品建议；
4. 自行补全用户未提供的信息；
5. 代替节点4生成面向用户的追问话术。

## 3. 两层校验机制

### 3.1 第一层：通用最低条件

所有病例均需满足以下条件：

- `animal`：能够明确动物种类；
- `disease_category`：能够根据明确症状判断疾病方向；
- `primary_symptom`：至少存在一个明确的主要症状；
- `category_required_fields`：满足对应疾病方向的最低字段要求。

任何一项不满足，均不能进入节点5，应路由至节点4补充信息。

### 3.2 第二层：分病类最低条件

不同疾病方向使用不同的字段规则。每个病类可以配置：

- `required_all`：其中所有字段都必须满足；
- `required_any`：其中至少一个字段必须满足。

建议使用以下结构保存规则：

```json
{
  "消化道疾病": {
    "required_all": [
      "animal",
      "primary_symptom"
    ],
    "required_any": [
      "feces_color",
      "feces_shape",
      "vomiting",
      "feed_intake"
    ]
  },
  "呼吸道疾病": {
    "required_all": [
      "animal",
      "primary_symptom"
    ],
    "required_any": [
      "cough",
      "wheezing",
      "breathing_status"
    ]
  },
  "神经系统疾病": {
    "required_all": [
      "animal",
      "primary_symptom"
    ],
    "required_any": [
      "convulsion",
      "standing_status",
      "movement_status"
    ]
  }
}
```

以上字段和病类仅为当前示例。后续可根据疾病知识库和业务需要继续扩充，但判断方式应保持一致。

## 4. 核心判定公式

节点3应采用以下逻辑判断是否满足最低诊断条件：

```text
diagnosis_ready
= 通用必填字段全部满足
  AND 对应病类的 required_all 全部满足
  AND 对应病类的 required_any 至少满足一项
```

不得因为信息数量较多就直接判定为满足，也不得因为仍有可选字段为空就直接判定为不满足。判断结果必须来自字段规则。

## 5. 疾病方向判断示例

| 明确症状 | 疾病方向 |
|---|---|
| 腹泻、呕吐、采食下降 | 消化道疾病 |
| 咳嗽、喘气、呼吸困难 | 呼吸道疾病 |
| 抽搐、转圈、共济失调、站立困难 | 神经系统疾病 |

“不舒服”“不对劲”“没精神”等笼统描述不能单独用于判断疾病方向。如果用户同时提供了笼统描述和明确症状，应以明确症状为准。

## 6. 路由逻辑

```text
如果 animal 为空：
  → diagnosis_ready = false
  → 路由至节点4，补充动物种类

否则，如果无法判断 disease_category：
  → diagnosis_ready = false
  → 路由至节点4，补充具体症状

否则，如果 primary_symptom 为空：
  → diagnosis_ready = false
  → 路由至节点4，补充主要症状

否则，如果对应病类的 required_all 未全部满足：
  → diagnosis_ready = false
  → 路由至节点4，补充缺失的必填字段

否则，如果对应病类的 required_any 一项都未满足：
  → diagnosis_ready = false
  → 路由至节点4，从 required_any 中选择最有价值的字段追问

否则：
  → diagnosis_ready = true
  → 路由至节点5，开展疾病知识库检索和辅助诊断
```

节点3只输出需要补充的字段，不直接生成用户可见的问题。具体追问话术由节点4生成。

## 7. 直接提供疾病名称的特殊情况

如果用户直接提供疾病名称，节点3可以跳过普通的疾病方向判断，但不能直接把用户提供的病名当作确诊结果。

节点3仍需校验后续诊断和方案生成所需的基础信息，至少包括：

- 动物种类；
- 日龄或生长阶段；
- 明确疾病名称或别名映射结果。

如果关键基础信息缺失，则进入节点4；信息完整后进入节点5，由节点5结合用户症状和知识库验证该疾病判断。

## 8. 完整示例

用户输入：

> 断奶仔猪拉黄色水样稀便一天了

节点2应提取：

```json
{
  "animal": "猪",
  "disease_name": null,
  "symptom": ["腹泻"],
  "age_group": "断奶仔猪",
  "duration": "1天",
  "quantity": null,
  "severity": null,
  "feces_color": "黄色",
  "feces_shape": "水样稀便",
  "temperature": null,
  "history_drug": null,
  "raw_text": "断奶仔猪拉黄色水样稀便一天了"
}
```

节点3的判断过程：

| 校验项 | 结果 | 是否满足 |
|---|---|---|
| 动物种类 | 猪 | 是 |
| 主要症状 | 腹泻 | 是 |
| 疾病方向 | 消化道疾病 | 是 |
| `required_all` | animal、primary_symptom均已满足 | 是 |
| `required_any` | feces_color、feces_shape已满足 | 是 |

因此：

```json
{
  "animal": "猪",
  "age_group": "断奶仔猪",
  "identified_disease": null,
  "disease_category": "消化道疾病",
  "category_identified": true,
  "diagnosis_ready": true,
  "treatment_info_ready": true,
  "diagnosis_missing_fields": [],
  "treatment_missing_fields": [],
  "priority_missing_fields": [],
  "question_type": "",
  "next_node": "节点5",
  "trigger_reason": "通用必填字段已满足，且消化道疾病的required_all全部满足、required_any至少满足一项"
}
```

## 9. 与节点5的关系

节点3判断 `diagnosis_ready=true` 后，节点5仍可能发现多个疾病无法有效区分。例如，黄色水样腹泻可能涉及多种疾病。此时应由节点5根据候选疾病的鉴别需要返回节点4，继续询问发病数量、是否呕吐、死亡情况、体温等信息。

因此，两个节点的判断标准不同：

- 节点3判断：信息是否达到“可以开始诊断”的最低门槛；
- 节点5判断：现有证据是否足以形成具有明显优势的主要诊断。

## 10. 评测要求

评测节点3时，应重点检查：

1. 疾病方向是否正确；
2. `required_all` 是否逐项校验；
3. `required_any` 是否至少命中一项；
4. 是否错误要求可选字段必须存在；
5. 是否遗漏真正的必填字段；
6. 缺失字段和优先追问字段是否准确；
7. `next_node` 与 `diagnosis_ready` 是否一致；
8. 是否越权输出具体疾病、治疗方案或产品推荐；
9. 是否编造用户未提供的信息；
10. 相同结构化输入是否能够稳定得到相同路由结果。

## 11. 核心设计原则

节点3应当是“规则驱动的流程门禁”，而不是“自由发挥的诊断模型”。

AI可以负责理解用户语言、映射字段和解释触发原因，但是否满足最低诊断条件，应由结构化规则决定。这样能够保证流程稳定、评测标准明确，并减少不同模型之间的路由差异。
